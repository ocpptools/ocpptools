# Changelog

Each package keeps its own changelog, generated by
[Changesets](https://github.com/changesets/changesets) from the changeset files
in each pull request. Versions follow [Semantic Versioning](https://semver.org/);
before 1.0.0, a minor release may contain breaking changes.

| ------------------------- | ------------------------------------------------------------------------ |

| `@ocpptools/schema-utils` | [packages/schema-utils/CHANGELOG.md](packages/schema-utils/CHANGELOG.md) |
| `@ocpptools/validator`    | [packages/validator/CHANGELOG.md](packages/validator/CHANGELOG.md)       |
| `@ocpptools/simulator`    | [packages/simulator/CHANGELOG.md](packages/simulator/CHANGELOG.md)       |

| `@ocpptools/schemas`      | [packages/schemas/CHANGELOG.md](packages/schemas/CHANGELOG.md)           |
| `ocpptools` (CLI)         | [packages/cli/CHANGELOG.md](packages/cli/CHANGELOG.md)                   |

Every release also has a
[GitHub release](https://github.com/ocpptools/ocpptools/releases) with the same
notes, tagged in the package format, for example `@ocpptools/core@0.3.1`.

`@ocpptools/core`, `@ocpptools/schema-utils`, and `@ocpptools/validator` are
versioned together. A release of one of them bumps the other two, even when only
their dependencies changed.
