# Support

OCPP Tools is maintained on a best-effort basis. There is no service-level
agreement or enterprise support commitment.

## Where to ask

| You have…                 | Go to                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------ |
| A question or an idea     | [GitHub Discussions](https://github.com/ocpptools/ocpptools/discussions)                               |
| A bug with a reproduction | [GitHub Issues](https://github.com/ocpptools/ocpptools/issues/new/choose)                              |
| A security vulnerability  | [Private vulnerability reporting](https://github.com/ocpptools/ocpptools/security/advisories/new) only |

## Before opening an issue

- Read the package README and the [documentation](docs/README.md).
- Check the [roadmap](ROADMAP.md) and its non-goals.
- Search existing issues and discussions.
- Confirm the package, version, OCPP version, Node.js version, and message
  type.
- Provide a minimal frame or payload that reproduces the problem.
- Redact CSMS URLs, credentials, certificates, idTag values, and production
  message IDs.

## Response expectations

Maintainers respond when time permits. Priority goes to security reports,
release-blocking bugs, and issues with clear reproductions.

## Scope of support

OCPP Tools helps you validate, build, simulate, and test OCPP-J messages. It is
not a conformance or certification tool, and the maintainers cannot certify
that a charging station or a CSMS complies with OCPP. For certification, contact
the Open Charge Alliance.
